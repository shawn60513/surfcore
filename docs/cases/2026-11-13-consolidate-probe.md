# 每晚記憶整理：首次真机跑通，修掉「话题」解析

## 为什么要专门跑一次

`maybeConsolidate()` 只在每天 23:00 后触发，而且会直接写她的记忆卡——上线以来 `lastConsolidated` 一直是空的，等于**这条唯一的写卡路径从未在真机跑过**。单元测试只能证明「给了格式正确的文本→解析→写档」没错，证明不了「模型真的会按那个格式回答」。

## 做法

`scripts/_tmp_consolidate_probe.mjs`（一次性，跑完删）：读某天日记 → `buildConsolidatePrompt()` → 在 `state/consolidate-probe` 开一个**临时工作区/临时会话**（不是她 lane 的会话）→ 送 prompt → 收 `turn/end` 的文本 → `parseConsolidateExtra()` 打印 → 归档会话。全程不碰记忆卡、不碰她的对话。

## 第一次结果（有价值）

模型给出了 3 条 `六|…`、`三|…` 和 `自己|…`，但「话还没说完的事」写成了：

```
深空當舖|他真去玩了我前幾天提過的那個，說很好玩…
```

——它把**话题名**当成了左边的标签。`parseConsolidateExtra()` 只认 `話題|`，这一整条被丢掉（`loops: []`）。

## 修法

1. 提示词加一句：「左邊固定寫『話題』兩個字，不要把題目放左邊；題目寫在右邊那句話裡。」
2. 解析放宽：`X|Y` 里 X 不是章号、不是 `自己`、不是 `話題`、长度 ≤ 8 → 当「未聊完的事」，正文改写成 `X：Y`（保留题目，别丢信息）。

## 第二次结果

```
三|他跑船，出港就沒網…
五|他去玩了我提過的《深空當舖》…
六|凌晨三點多他睡不著…
話題|他說下次要讓我也玩到《深空當舖》，還沒實現
自己|在練歌，想唱到真的有人在聽
```

解析：3 條 entries、1 條 loops、1 句 self —— **格式全对**。

## 代价与结论

- 一次整理约 1,150 字提示词 + 几十字输出，一晚一次，可以接受。
- 这条链路现在有了真机证据：模型能按格式回来，解析能吃下它的小偏差。
