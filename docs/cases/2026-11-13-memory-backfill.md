# 2026-11-13 记忆卡回填 + 「记得的事」只带最新几条

## 现象

用户问「小愛的記憶會出問題嗎」。查下来发现：记忆卡（`~/.dsh/xingxi/会话/爱弥丝/记忆卡.md`）停在 **11-06 23:44**，而日記一直写到 11-13；拾星的摘星任务 `{"完成": true, "已到": "2026-11-06"}` 卡住没再跑，`原始对话/` 也只有 11-06 那一份。

结果是：11-07 到 11-12 的事她全写进日記了，但日記**不进提示词**，她读不到。

## 修法一：把夜间整理开回来（用户选 A）

- `config.json` 的 `discord.lane.consolidateHour`：`-1` → `23`（备份 `config.json.bak-<ts>`）。
- 每晚 23:00 后第一轮：读当天日記 → 让她挑最多 3 条、按 `章號|內容` 交回 → 代码 `appendCardEntries()` 写卡（写前自动备份）。

## 修法二：回填 11-07 ~ 11-10

把四篇日記（11-07 6.5K、11-08 0.5K、11-09 1.1K、11-10 2.0K）读完，按同样口吻整理成 4 条写进卡（`appendCardEntries`，备份 `记忆卡.md.bak-20261113-0358-03`）：

- 三｜他在海上工作，出港就没网；能连上会先说一句「我还在，没有不理你」。

- 六｜11-09 凌晨有网那句「知道你还在我就放心了」；11-10 晚餐照片（大肠/排骨/肉燥饭 + 无糖水果酒 196）、輝達那条（只有画面没声音）、42 分钟片子里那句「解锁过的地图，以后不去了也一直亮着」。

11-13（今天）的日記交给今晚的夜间整理。

## 修法三：`readMemoryBrief()` 改成「取每章最后 3 条」

原来是从头往后拼、超过 500 字直接 `slice` 截断——卡片是往**后**追加的，等于她永远只记得最早那几条，新加的一条都进不来（回填白做）。

现在：每章取最后 3 条 → 按三/五/六顺序拼 → 超长就从**最旧**的开始丢，保住最新的。顺手把条目末尾的「。；」清掉，避免出现 `。；`。

实测 brief：483 字，含 11-07 与 11-09/10 两条新内容。
