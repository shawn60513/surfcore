# 2026-11-08 連發好幾條只回一次（她連說兩次晚安）

## 现象

用户说：「為什麼她剛剛連續說了兩次晚安」。DM 里 17:51 那几秒：

- 17:51:15 用户：「好喔」
- 17:51:17 用户：「晚安」
- 17:51:38 她：「嗯，晚安」
- 17:51:43 她：「晚安～」

## 根因

`src/discord-lane.js` 的 `tick()` 是**逐条**处理新消息的：`for (const msg of messages) { ... runTurn(); send(); }`。

他 1.5 秒里发了两条，同一轮 fetch 都拿到了，但每条各跑一次模型、各发一次 → 两次「晚安」。

（不是重复投递：`state/discord-lane.json` 的 history 里也是两条独立的 bot 记录，时间差 5 秒，对应两轮。）

## 修法

- 新增导出 `combineUserLines(lines)`：逐行接起来、去空行。
- `tick()` 改成**先收集**本轮所有新消息（跳过 bot 自己的），拼成一份内容（多行），图片附件全部合并，只跑一次 `runTurn()`、只 `send()` 一次；水位推到本批最后一条 id。
- 失败重试语义不变：出错了水位不动，下一轮重试整批。
- `scripts/test-discord-lane.mjs` 第 15 组：合并多行、空白/`null` 不算、空数组。

## 验证

- `node scripts/test-discord-lane.mjs` → **15 组通过**。
- `node scripts/test-audit.mjs` → **149/149**，exit 0。

## 副产品

顺带发现：她连着说两遍，其实也暴露「每轮都要说一句完整的」这个问题。已经在工作区规则里写了「不是每次都要答得完整」，但用户连发两条时，合并成一轮更自然——真人也不会对「好喔」和「晚安」各回一次。

## 遗留

- 合并窗口就是一次 poll（`pollMs=60000`）：如果两条消息落在两次 poll 之间，还是会被拆成两轮。真要严格，得在「最后一条消息不到 N 秒就先等等」上加滞后（未做；60 秒 poll 下很少见）。
