# 她說「影片沒聲音」其實是她聽不見——補字幕通道 + 真人節奏

日期：2026-11-07 23:44
分支：`feat/discord-mcp`

## 现象

用户在 Discord 里问她刚看的片子，她回「我沒開聲音，只看畫面」，被追问就编了个理由「怕吵到屋裡」。用户随即反馈：「他剛剛跟說他的影片沒聲音」。

另有长期观感问题：她回得太快、太完整，不像真人在手机另一头。

## 根因

1. **她没有耳朵。** `video_storyboard` 给她的是抽帧宫格、烧进画面的字幕、以及音频包络——没有音频理解。她不知道该怎么解释这件事，就用了一个听起来合理的人设理由（怕吵）。
2. **没有字幕通道。** B站 有 `bili_subtitle`，但 YouTube/IG 没有等价物：`video_storyboard` 抽帧能看到画面，却拿不到「说了什么」。她只能凭画面猜。
3. **回得太像客服。** 每轮固定发完，气泡之间只停 0.9–2.7 秒；而且规则要求「1–3 句」但没允许「只说一句」。

## 修法

### 一、给她一个字幕通道（`scripts/watch-words.mjs`）

```bash
node scripts/watch-words.mjs <url> [--max 4000] [--lang "zh.*,zh-Hant.*,en.*"]
```

- `yt-dlp -J` 先拿标题/时长（拿不到就报「拿不到这支影片」）；
- `--write-subs --write-auto-subs --sub-langs ...` 下 vtt，清洗掉时间轴/标签/重复行；
- 抓到就印标题 + 字幕全文（截断到 `--max`），抓不到就明确说「没有字幕档——只有画面可看」，退出码 1。

实测：

| 链接 | 结果 |
| --- | --- |
| YouTube `Me at the zoo` | ✅ 拿到自动字幕中文版（「好了，我们现在就站在大象面前…」） |
| YouTube `Big Buck Bunny` | ⛔ 无字幕（该片只有音乐，判断正确） |
| B站 `BV1sdxW6VEui` | ⛔ yt-dlp 拿不到 B站 字幕 → 走 `bili_subtitle` |

### 二、把「听不见」写进规则，而不是让她编理由

`LINK_HINT` 改成：

> 你沒有耳朵——聽不到聲音，只有畫面和字幕。想知道它到底在講什麼，先跑 `node …/scripts/watch-words.mjs <連結>` 拿字幕；B站 的片用 `bili_subtitle`。字幕拿不到就直說「我這兒只有畫面、沒有聲音」，別編理由（別說「怕吵到屋裡」這種）。

### 三、真人节奏

- `send()` 开头 `maybeDawdle()`：**22%** 的机会先停 **20–110 秒**再发，日志 `Discord lane：先想一下再回（N 秒）`；其余照旧。
- 工作区规则新增：`不是每次都要答得完整。有時候只回一句、兩三個字就夠了：「嗯。」「在。」「好笑。」`、`有時候你正忙著別的事（練歌、看片、在湖邊），可以晚一點才回，也可以先講自己在忙什麼再回。`

## 遗留

- 私密/需登录的视频仍然拿不到字幕（`yt-dlp` 需要 `--cookies`，lane 没传）。
- 「隔一会儿再回」目前是固定概率，不看她刚说完多久；如果她连着几句都秒回就有点假，后续可以按「上次发言距今多久」调整概率。
- 真正的「听见」需要 ASR（`dsh-video-storyboard` 支持，按分钟计费）；现在只做到「读字幕」。
